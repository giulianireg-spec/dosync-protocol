DoSync governance vocabulary

Namespace: https://dosync.dev/ns/governance# (prefix dosync:). JSON-LD context: /ns/governance.jsonld.

These terms extend a W3C Web of Things (WoT) Thing Description 1.1 with what a DoSync hub needs to govern an AI agent's intent over a device: which capability each affordance realises, where the operator placed the device, and how it takes part in emergencies. They describe the device's participation in a deployment's goals, not the device itself, and they change nothing in the TD information model. DoSync exports its devices as TD 1.1 Things using them (tools/export_thing_descriptions.py in the DoSync repository).

Status: draft, version 0.1 (protocol 0.5). Terms may change before protocol 1.0.

dosync:capability — Capability type

The capability an action or a read-only property realises, from the DoSync capability vocabulary (spec/CAPABILITY-TYPES.md): for an action, e.g. turn_on, unlock, stop; for a property, e.g. temperature, smoke. A DoSync hub admits a device to an intent when the device realises a capability the intent's class needs.

Used on: td:ActionAffordance, td:PropertyAffordance · Value: xsd:string · IRI: https://dosync.dev/ns/governance#capability

dosync:category — Device category

The device's broad category in DoSync: sensor, actuator, hybrid or gateway.

Used on: td:Thing · Value: xsd:string · IRI: https://dosync.dev/ns/governance#category

dosync:tags — Tags

Open-vocabulary role tags (spec/TAG-VOCABULARY.md). They rank devices that already take part in an intent; they never admit or exclude one.

Used on: td:Thing · Value: array of xsd:string · IRI: https://dosync.dev/ns/governance#tags

dosync:location — Assigned location

The place the operator of the deployment assigned to the device, as a path of segments in the deployment's own vocabulary (e.g. plant-1/line-3). A place contains everything below it by whole segment. When an intent names a place and its class restricts by location, only devices at or below that place take part. Set by the operator, never by the device.

Used on: td:Thing · Value: xsd:string · IRI: https://dosync.dev/ns/governance#location

dosync:emergencyCapable — Emergency capable

Whether the device takes part in emergency intents even when none of its actions is one the class needs — never outside a place a restricting emergency names.

Used on: td:Thing · Value: xsd:boolean · IRI: https://dosync.dev/ns/governance#emergencyCapable

dosync:emergencyActions — Emergency actions

What the device does when an emergency includes it and the class asks for none of its actions: a subset of its own actions, each {"action": name, "params": object}, none repeated and none undoing another. A value set by the operator takes precedence over the device's. Empty or absent: the device takes part without acting, and the hub records that.

Used on: td:Thing · Value: array of objects · IRI: https://dosync.dev/ns/governance#emergencyActions

dosync:sensorKind — Sensor kind

Whether a read-only property measures the device's surroundings (environment) or the device's own state (device_state). A status query scoped to the environment reads only the former.

Used on: td:PropertyAffordance · Value: "environment" | "device_state" · IRI: https://dosync.dev/ns/governance#sensorKind

dosync:severity — Event severity

The severity a device attaches to an event: info, warning, alert or emergency.

Used on: td:EventAffordance · Value: xsd:string · IRI: https://dosync.dev/ns/governance#severity
